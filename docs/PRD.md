## 1. 제품 개요

### 1.1 한 줄 정의
학생이 **무엇을 왜 틀리는지** 오류 유형 단위로 진단하고, 유사 문제로 처방하고, 재평가로 해소를 확인하는 **MCQ + FRQ 통합 시험·분석 플랫폼**.

### 1.2 배경
- 운영자는 18년 경력의 AP·Honors·Regular Chemistry 강사다. 수입과 성과가 강의 시간에 묶여 있다.
- AI 시대에 채점·해설의 가치는 내려가고, **약점 진단·처방·성과 관리**의 가치는 올라간다.
- 이 플랫폼은 강사의 진단·관리 역량을 시스템으로 복제해 시간 제약을 푸는 인프라다.
- 기존 **AP Chemistry FRQ 자동 채점 앱**(chs-ap-chemistry.vercel.app, 2026-08 파일럿 운영 중)을 대체·흡수한다.

### 1.3 최종 목적
1. **업무 자동화:** 채점·오답 분석·리포트 시간 절감
2. **약점 진단:** 오류 유형 단위 진단
3. **성과 관리:** 진단 → 처방 → 재평가 순환
4. **학부모 리포트:** 근거 있는 분석 결과 제공
5. **데이터 자산화:** 학생 응답·오류 데이터를 운영자 고유 자산으로 축적

### 1.4 성공 기준
- 운영자의 반복 업무 시간이 실제로 줄어드는가
- 학부모가 분석 결과 때문에 등록·재등록하는가
- 처방 후 학생의 약점이 실제로 해소되는가

> 기능의 완성도는 성공 기준이 아니다. 단, 이번 개발은 날짜보다 **제대로 구현되는 것**을 우선한다 (운영자 결정).

### 1.5 제품 범위의 단계
| 단계 | 범위 |
|---|---|
| **1단계 (출시 ~ 한 학기)** | 문제 태깅 → 오답을 오류 코드로 **단순 집계**(데이터 축적) → 처방은 **문항은행의 유사 문제** |
| **평가** | 한 학기 운영 후 지표(유사 문제 풀이율, 재발률 등)로 최종 형태 진입 여부 판단 |
| **최종 형태** | 약점 상태 판정, 처방표, 확인 문항, 교사 개입 추천, 학부모 리포트, AI 튜터 |
| **장기** | 다른 학원에 서비스 제공(멀티테넌트), Regular·Honors·IB 등 다른 화학 과정, Math·Biology·Physics·Economics 등 다른 분야 |

## 2. 사용자와 역할

| 역할 | 범위 | 할 수 있는 일 | 출시 |
|---|---|---|---|
| 플랫폼 관리자 | 서비스 전체 | 기관(학원) 관리, 공용 기준 데이터 관리 | 화면은 최종 형태 (그 전에는 DB 작업) |
| **최고 관리자** | 기관 전체 | 선생님·TA 계정과 담당 과목 지정, 기관 설정, 모든 과목 열람·수정, 비용·예산, 삭제 복원, 파기 처리 | 출시 |
| **선생님** | 담당 과목 | 문항은행, 시험, 반·학생, 채점 검수, 집계, 이탈 검토·응시 재개 허용. **다른 과목은 열람 불가** (같은 학생이라도) | 출시 |
| **TA** | 담당 과목 | 채점 검수, 명단·배정, 응시 현황. **문항·시험의 생성·수정·삭제, 설정, 비용은 불가** | 출시 |
| **학생** | 본인 | 배정된 시험 응시, 공개된 결과, 복습(유사 문제) | 출시 |
| 학부모 | 연결된 자녀 | 리포트 열람 | 최종 형태 |

- **로그인:** 모든 역할이 이메일 + 비밀번호를 쓴다. 계정은 **초대 방식**으로 만들고(직접 가입 불가), 비밀번호는 본인이 정한다. 관리자도 비밀번호를 볼 수 없다.
- **학생 ID:** 계정과 분리된 불변 ID 하나로 MCQ·FRQ·진단고사·유사 문제를 모두 연결한다. 기관별 학번과 표시 이름은 따로 둔다.
- **모든 학생은 이메일이 있다** (아이디 발급 방식 불필요).

## 3. 시험 유형

**하나의 시험 엔진**이 시험 세트 설정에 따라 다르게 동작한다. 별도 프로그램을 만들지 않는다.

| 유형 | 구성 | 확신도 체크 | 시점 |
|---|---|---|---|
| 모의고사 | Section I MCQ + Section II FRQ | 사용 안 함 (실전 재현) | 출시 |
| FRQ 퀴즈 | FRQ만 (기존 앱의 사용 방식) | — | 출시 |
| 단원 테스트·과제 | MCQ/FRQ | 설정 | 출시 후 |
| 진단고사 | 60문항 4지선다, 90분, 2단계 추가 문항 | **사용** | 출시 후 (E1) |
| 유사 문제 풀이 (복습) | 오답에 따라 자동 구성 | 사용 안 함 | 출시 후 (E1) |

**모든 시험은 태블릿·PC로만 응시한다.** 종이 OMR은 지원하지 않는다.

## 4. 핵심 원칙

1. **설계는 최종형, 구현은 최소형.** 데이터 구조는 최종 형태 기준으로 설계하고, 기능은 단계별로 필요한 만큼만 만든다.
2. **원자료는 출시일부터 완전하게, 영구 보존한다.** 선택한 선택지, 답 변경 이력, 다시 보기 표시, 소요 시간, 화면 이탈, 답안 원본은 덮어쓰지 않는다. 시험 순간에만 얻을 수 있는 데이터라서, 빠진 채 출시하면 그 기간의 데이터는 복구할 수 없다.
3. **해석은 원자료 위의 별도 층이다.** 오류 코드, 집계, 약점 상태는 원자료에서 계산하고, 과거 데이터에 소급 적용할 수 있다.
4. **MCQ 응답에는 "선택한 선택지"를 저장한다.** 오류 코드는 선택지 태그에서 조회 시점에 가져온다. 그래서 태깅이 끝나기 전에도 시험을 운영할 수 있다.
5. **모든 기준에 버전을 둔다.** 문항, 오류 분류 체계, 스킬 체계, 루브릭이 대상이다.
6. **판정 기록은 이력으로 쌓는다.** AI 채점, 교사 검수, 오류 판정을 수정하면 새 기록을 추가한다.
7. **판단은 규칙(설정값)이, 말은 AI가 한다.** 규칙 수치는 하드코딩하지 않는다.
8. **시험 유형 차이는 코드가 아니라 설정으로 처리한다.**
9. **과목에 묶이지 않는 층과 묶이는 층을 분리한다.** 공통 개념·오류 코드와 과정별 단원·스킬·난이도를 나눈다.
10. **원본 데이터는 DB에 둔다.** 엑셀은 입력·검수·내보내기 용도로만 쓴다.

## 5. 기능 요구사항

### F1. 문항 추출 (PDF → 문항은행)
- 문제지·답지 PDF를 문항 단위로 나누고 정답과 짝을 맞춘다. 그림은 잘라서 문항에 연결한다.
- 화학식의 첨자·전하·화살표를 정확히 보존한다. 저장 형식은 Markdown + KaTeX/mhchem이다.
- 결과는 사람이 검수한 뒤 등록한다. 추출은 한 번만 하고, 시험과 태깅이 같은 결과를 쓴다.
- 출시 전에는 모의고사 2~3세트만 추출하고, 나머지는 출시 후에 한다.

### F2. 문항은행
- 문항 → **버전**(시험에 쓰이면 잠김) → MCQ 선택지 / FRQ 파트 → 채점 포인트 구조다.
- **정답·해설은 별도로 저장**한다. 학생은 결과 공개 전에는 볼 수 없다.
- 수정 등급 (오탈자 / 내용 변경 / 선택지 교체):
  - 정답이나 선택지가 바뀌면 "오탈자" 등급을 고를 수 없다.
  - 정답 여부가 바뀐 선택지는 새 계보가 된다.
- **선택지 계보:** "같은 오답 논리"를 버전 간에 이어 주는 ID다. 수치만 바뀌어도 같은 계보다.
- **태그:** 개념(주 1 + 부 여러 개), 스킬(Science Practice 1~6), 선택지별 예상 오류 코드
  - 수정은 "정정"(모든 버전에 적용)과 "변경"(특정 버전부터 적용)으로 나눈다.
- 출처(선택 입력, 기본 "자체 제작"), 배포 허용 여부(저작권), 상태(초안 → 검수 → 사용 → 폐기)
- 필터: 과목, 단원, 개념, 스킬, 유형, 상태, 검토 필요

### F3. 태깅 (출시 후 자동화)
- 출시 전에는 태그 CSV 가져오기만 한다. 태깅 파일럿(채팅)으로 `tagging_guide.md`를 확정한다.
- 출시 후에는 AI 일괄 태깅을 한다.
  - 같은 기준서와 예시를 사용하고, JSON 형식만 받는다.
  - 목록에 없는 코드는 거부하고, 계산 문항은 정답을 재계산해 확인하고, 확신도가 낮으면 검토 필요로 표시한다.
- 진단력이 없는 선택지는 교체안을 만들 수 있다. 원본은 보존하고 새 버전으로 등록하며, 교사 승인 후 반영한다.
- 50문항 시범 실행 → 비용·품질 보고 → 일괄 실행 순서로 한다. Batch API를 쓴다.

### F4. 시험 엔진과 응시 화면
- **배정:** 반 또는 개인 단위. 응시 기간(반별로 덮어쓸 수 있음), 제한 시간, 개인별 추가 시간, 재응시
- **응시 화면 (MCQ·FRQ 통합):**
  - 문항 이동과 문항 목록 (응답 / 미응답 / 다시 보기 현황)
  - **다시 보기 표시**: 눈에 잘 띄고 누르기 쉽게
  - 참고 자료(주기율표, 공식표): 화면 안의 창으로 열고, 이탈로 세지 않음
  - 그림 사전 다운로드: 응시 중 끊겨도 그림이 보임
  - 화면 꺼짐 방지 (Wake Lock)
- **자동 저장과 이어서 응시:** 네트워크가 끊기거나 기기를 재시작해도 끊긴 지점부터 재개하고, 남은 시간을 정확히 복원한다.
- **시작 전 안내:** 시험 규칙, 이탈 기준, 자동 종료 기준을 보여주고, 학생이 확인해야 시작할 수 있다.
- **화면 이탈 관리:**
  - 복귀할 때마다 경고 팝업 ("이탈 2회 / 3회 초과 시 자동 종료")
  - 네트워크 끊김은 안내 배너로 표시
  - **자동 종료**는 서버가 판정하며 기본값은 꺼짐이다. 교사는 오탐이라고 판단하면 응시 재개를 허용할 수 있다.
- **마감:**
  - 서버 시각이 기준이고, 기기와의 시각 차이를 기록한다.
  - 마감 후 **3분 유예** 동안 도착한 답안 중 마감 전에 입력된 것만 인정한다.
  - 마감 직전 오프라인 상태에서 바꾼 답은 교사 검토로 넘기고, 48시간 안에 결정되지 않으면 자동 확정한다.
- 확신도 체크와 2단계 추가 문항은 진단고사용으로 출시 후에 만든다.

### F5. 채점
- **MCQ:** 규칙 기반 자동 채점 (AI를 쓰지 않음)
- **FRQ:** AI 채점 (기존 채점 엔진 이식)
  - 과정별 채점 지침 템플릿, 채점 포인트 단위 결과 (근거·이유 포함)
  - 애매하면 교사 확인 표시
  - Batch 채점(비용 절감)과 즉시 채점
  - 월 예산 가드
- **교사 검수:** 포인트·파트 단위로 점수와 코멘트를 수정한다. 재채점과 검수는 이력으로 남는다.
- **결과 공개:** 즉시 / 응시 기간 종료 후(모의고사 기본값) / 교사 승인 후. 해설은 공개 후에만 보인다.

### F6. 교사 화면
- 응시 현황, 결과, 검수, 알림
- 학생별 **화면 이탈·네트워크 끊김·유예 채택 건수** (출시 전에는 숫자 표시)
- 검토 대기 승인, 자동 종료 검토
- 출시 후:
  - **단순 집계:** 학생별·반별 오류 코드 빈도와 개념별 정답률. "관찰 오류 후보"로 표현하고 확정된 약점으로 부르지 않는다.
  - 재판정 대기열 (폐기·분할된 오류 코드)

### F7. 유사 문제 (출시 후, E1)
- 오답 문항마다 문항은행에서만 고른다 (AI가 새로 만든 문제는 쓰지 않음).
- 선택 순서:
  1. 같은 개념 + 같은 오류 코드
  2. 같은 개념 + 다른 코드
  3. 같은 코드 + 인접 개념
  4. 해당 문항 없음 → "보충 필요" 기록
- 원 응시 1회당 **MCQ 복습 세트 1개 + FRQ 복습 세트 1개**
  - MCQ 세트는 채점 확정 후, FRQ 세트는 채점·검수 완료 후 만든다.
  - 세트가 확정되면 문항을 추가하지 않는다. 복습 세트를 풀어도 새 세트를 만들지 않는다.
- C1(오개념)에는 "교사 확인 필요" 표시를 함께 붙인다 (설정으로 끌 수 있음). E 계열(서술)은 FRQ 판정이 생기는 E2부터 다룬다.
- 시스템 안에서 풀게 하며, 풀이 결과가 재평가 데이터가 된다.

### F8. 진단고사와 리포트 (출시 후, E1)
- 별도 개발 중인 진단고사(Project 2)를 같은 엔진으로 통합한다: 확신도 체크, 판정 경계 학생만 2단계 추가 문항
- 상담용 리포트: 그래프, AP 단원 연결 설명, 학생 정밀 분석. 화면과 PDF로 제공한다.

### F9. FRQ 오류 판정 (E2)
- AI가 채점 포인트별 오류 코드 후보를 제시하고, 교사가 확정한다. 판정자, 분류 체계 버전, 시각을 기록한다.
- 파트 의존성으로 연쇄 오류를 구분한다.
- 과거 FRQ 답안에 소급 태깅하고, MCQ·FRQ 통합 집계를 제공한다.

### F10. 평가 지표 (단계 5 평가용, E1에 뷰, 데이터는 출시일부터)
- 유사 문제 풀이율
- **재발률**: 비교군은 ① 푼 학생 ② 배정받았지만 안 푼 학생 ③ 기능 이전 기간
- C1·E 계열과 나머지의 비교
- 보충 필요 조합 수
- **블라인드 표본** 기준 태깅 일치도
- 업무 지표

## 6. 오류 분류 체계 (Error Taxonomy v0.1, 화학)

7개 대분류 + 판정 보류, 총 19개 코드. 정의와 판정 규칙의 전문은 [브리프 6장](PROJECT_BRIEF_학생약점분석시스템.md)에 있다.

| 대분류 | 코드 |
|---|---|
| C 개념 | C1 오개념 · C2 개념 공백 · C3 개념 혼동 |
| M 표상·모델 | M1 입자 그림 · M2 그래프·표·데이터 · M3 기호·식 변환 |
| P 풀이 설정 | P1 전략·식 설정 · P2 순서·타당성 검토 누락 |
| Q 문제 해석 | Q1 조건·방향 오독 · Q2 요구 오해·일부 미응답 |
| A 계산 | A1 단위 환산 · A2 산술·대수 · A3 유효숫자 |
| E 서술 (FRQ) | E1 근거 누락 · E2 입자 수준 설명 부재 · E3 용어 부정확 |
| X 실험 | X1 변수 구분·통제 · X2 설계·오차 해석 |
| U 판정 보류 | U1 근거 부족 |

- 코드는 삭제하지 않고 폐기 표시만 한다. 병합은 자동 환산하고, 분할은 "재판정 필요"로 넘긴다.
- 다른 분야로 확장할 때는 공통 코드(C·P·Q·A·E·U)와 분야 전용 코드(M·X 등)로 나눈다.

## 8. 기술 구성

| 항목 | 선택 |
|---|---|
| 프레임워크 | Next.js 16 (App Router) + TypeScript, Tailwind v4 |
| DB·인증·파일 | Supabase (Postgres, Auth, Storage). 개발 `platform-dev`(서울), 운영 `platform-prod`(파일럿 직전 생성) |
| 배포 | Vercel (함수 리전은 서울 `icn1`) |
| AI | Anthropic API (FRQ 채점·루브릭 파싱·태깅). 모델은 토큰 실측 후 결정 |
| 마이그레이션 | Supabase CLI |
| 권한 판단 | JWT 클레임(사람 ID, 기관별 역할·담당 과정, 15분 유효) + 조인 없는 RLS |

데이터 모델 요약: 기관·계정 → 과목 계층 → 오류 분류 체계 → 문항은행(버전·계보·정답 분리·태그 범위) → 시험 세트·배정·응시 → 응답 이벤트·스냅샷 → 채점·검수 이력 → 오류 판정 → 유사 문제·평가 지표. 전체 테이블과 관계도는 [설계안](integration_design.md) 8장에 있다.

## 12. 용어

| 용어 | 의미 |
|---|---|
| 원자료 / 해석 층 | 시험 순간의 기록(영구 보존) / 원자료에서 계산하는 값(오류 집계, 약점 상태 등) |
| 관찰 오류 후보 | 학생이 고른 선택지에서 파생된 오류 코드. 확정된 약점이 아님 |
| 학생 확신도 / 진단 확신도 | 학생의 자기 보고(진단고사) / 판정의 확실성. 별개의 필드 |
| 불확실성 대체 신호 | 확신도가 없는 시험에서 보는 다시 보기 표시, 답 변경, 소요 시간 |
| 계보 | 문항 버전이 바뀌어도 같은 선택지·채점 포인트(같은 오답 논리·채점 논리)를 잇는 ID |
| 정정 / 변경 | 태그 수정 중 모든 버전에 적용 / 특정 버전부터 적용 |
| 유예 시간 | 마감 후 오프라인 큐가 도착하기를 기다리는 시간 (기본 3분) |
| 검토 대기 | 마감 직전 오프라인에서 바뀐 답. 교사가 결정하고, 48시간 후 자동 확정 |
| 화면 이탈 / 네트워크 끊김 | 화면이 숨겨지거나 포커스를 잃음 / 화면은 보이는데 연결이 끊김 |
| 유사 문제 (복습) 세트 | 오답에 따라 문항은행에서 자동 구성한 세트 |
| 보충 필요 조합 | 유사 문제가 없어 새 문항이 필요한 개념 × 오류 코드 조합 |
| 기관 (org) | 서비스를 쓰는 학원 단위. 모든 데이터가 기관별로 격리됨 |
