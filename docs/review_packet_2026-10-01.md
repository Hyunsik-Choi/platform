# 검증 요청: 학생 약점 분석 시스템 — 단계 0~1 진행 결과 (2026-10-01)

## 요청 사항
아래는 Claude Code와 진행한 "PROJECT_BRIEF_학생약점분석시스템 v3.1" 0장 작업(현황 분석 → 통합 설계)의 결과와, 그 과정에서 운영자가 내린 결정이다. 다음을 검토해 주기 바란다.

1. **결정의 타당성:** 특히 "기존 앱을 확장하지 않고 새 프로젝트로 분리"와 "멀티테넌트 설계"가 브리프의 목적과 원칙(4장)에 맞는지
2. **브리프와의 충돌:** 브리프 내용을 바꾼 부분(단계 재정렬, FRQ 데이터 이전 범위 축소 등)이 정당한지, 놓친 요구사항은 없는지
3. **설계 위험:** 데이터 구조·권한·원자료 수집 설계에서 나중에 비싸게 고쳐야 할 부분이 보이는지
4. **비용 추산:** 계산과 가정이 합리적인지

함께 첨부하는 문서: 브리프 원문, `current_state.md`(현황 분석서, 승인됨), `integration_design.md`(통합 설계안 v2, 승인 대기)

## 1. 현황 분석 요약 (승인됨)

**기존 FRQ 자동 채점 앱**
- 운영 중: chs-ap-chemistry.vercel.app
- 스택: Next.js 15 + TypeScript, Supabase(Postgres·Auth·Storage, RLS), Vercel, Anthropic API(채점 Opus 5, Batch API)
- 규모: 실제 학생 19명(응시 11명), 주당 FRQ 약 2문항, 제출 43건

**발견된 문제**
- **개발·운영 DB가 같다:** Supabase 프로젝트 1개를 로컬 개발과 운영이 함께 쓴다. 마이그레이션은 SQL Editor에서 수동 실행하고 적용 기록이 없다. 별도 백업도 없다.
- **문항이 시험지에 종속된다:** 문항은행이 없다. 파트 (a)(b)는 JSON 안에만 있고, 답안도 문항당 1개다.
- **데이터 손실 경로가 있다:**
  - 재채점 시 이전 채점과 교사 검수가 삭제된다.
  - 루브릭을 수정하면 덮어쓴다.
  - 시험지·폴더·문항을 삭제하면 CASCADE로 학생 답안·채점까지 삭제된다.
  - 같은 시험은 1회만 응시할 수 있다.
- **오류 분석 데이터가 없다:** 오류 코드, 개념, 스킬 태그가 없고, 분류는 AP Unit 1~9 + 자유 텍스트뿐이다.
- **보안:**
  - 학생은 이름+이메일만으로 로그인하고, 로그인할 때 입력한 이름으로 프로필 이름이 덮어써진다.
  - TA·학생 비밀번호를 평문으로 저장한다.
- **재사용할 만한 자산:** 학생 UUID 체계, 클래스·배정·응시 기간·타이머, 포인트별 채점 결과(evidence·reasoning 포함), Batch 채점 파이프라인, 비용 예산 가드

**백업 (2026-10-01, 읽기 전용)**
- 테이블 21개 전체, Auth 사용자 25명, Storage 파일 157개(10.3MB)를 저장소 밖에 보관했다.
- 운영 DB 컬럼이 마이그레이션 0001~0021과 일치함을 확인했다.
- 한계: `pg_dump`가 아니라서 함수·RLS·비밀번호 해시는 미포함이다. 완전 백업 방법은 미정이다.

## 3. 통합 설계안 v2 핵심 (승인 대기)

**구조**
- 멀티테넌트
  - 모든 기관 소유 데이터에 `org_id`를 두고, RLS가 `has_org_role()` 하나로 기관 경계와 과목 범위를 강제한다.
  - Storage 경로(`org/<org_id>/…`), AI 비용, 예산, 규칙 설정도 기관별로 나눈다.
  - 분야·과정·공통 개념·공통 오류 코드는 플랫폼 공용이고, 기관은 자체 항목을 추가할 수 있다.
- 계정
  - 사람 단위 `profiles`(= Auth UUID = **학생 ID**, 모든 원자료의 FK) + 기관 소속 `org_members`(역할, 기관 내 학번) + 과목 범위 `member_scopes`(과정 또는 분야)
  - 플랫폼 관리자는 별도로 둔다.
  - 계정은 초대 방식으로 만들고, 비밀번호는 Auth 해시로만 저장한다(평문 사본 없음). 관리자는 재설정 메일이나 임시 비밀번호만 발급할 수 있다.
  - 학생 단일 세션 정책은 기관 설정으로 켜고 끈다.
- 과목 계층: 분야 → 과정 → 교육과정 기준(버전) → 단원. 개념은 분야 안에서 과정 간 공통이다(브리프 원칙 8 일반화). 스킬 체계는 과정별이다.
- 오류 분류: 화학 Taxonomy v0.1을 그대로 넣는다. 공통 코드와 분야 전용 코드로 나눌 수 있게 구조를 열어 두고, 버전·폐기·변환표를 둔다.
- 문항은행
  - 문항 → 버전(응시에 쓰이면 잠기고, 수정하면 새 버전) → MCQ 선택지 / FRQ 파트 → 채점 포인트
  - 개념·스킬·오류 태그는 버전과 분리된 이력 층이라, 태그를 수정하면 과거 응답 해석에 자동 반영된다.
  - 문항 유형은 등록제로, 숫자 입력·그래프 등을 나중에 추가할 수 있다.
- 시험 엔진
  - 시험 세트 → 섹션 → 문항 버전(고정). 배정(클래스·개별, 응시 기간 override), 응시(attempt_no로 재응시 허용)
  - 설정은 jsonb로 둔다: 확신도, 참고 자료, 결과 공개, 채점 모드
  - 삭제는 전부 soft delete이고, 응시 기록으로 이어지는 FK는 RESTRICT다.
- 원자료
  - MCQ 행동 전부를 `response_events`(append-only, 멱등 키, IndexedDB 오프라인 큐)에 남기고, `item_responses` 스냅샷과 소요 시간은 이 로그에서 계산한다.
  - FRQ 답안은 파트별로 받되, 문항 전체 사진도 허용한다.
- 채점
  - MCQ는 규칙 채점이다.
  - FRQ는 기존 채점 엔진을 이식하되, 프롬프트를 과정별 템플릿으로 바꾸고 결과를 채점 포인트 단위 행으로 정규화한다.
  - 재채점·검수는 이력으로 쌓는다(`is_current`).
- 오류 판정
  - MCQ는 선택지 태그에서 뷰로 파생한다(복사 안 함).
  - `error_judgments`는 판정자(AI/교사/규칙), 분류 체계 버전, 진단 확신도와 함께 이력으로 쌓는다.
  - 학생 확신도와 진단 확신도는 다른 테이블에 둔다.
- 운영
  - 기관별 `ai_usage_log`(Batch 할인 반영, 채점 외 용도 포함), `audit_log`, 기관별 `app_settings`
  - DB 타입 자동 생성, RLS 기관 간 누출 테스트

**개발 단계 (브리프 9장 재정렬)**

| 단계 | 내용 |
|---|---|
| P0 | 기반: 저장소, Supabase 개발·운영, CLI 마이그레이션, 백업, CI |
| P1 | 기관·계정·권한, 과목 계층, 클래스·배정, 시험 엔진 골격 |
| P2 | MCQ: 문항은행, PDF 추출 v1, 응시, 원자료, 규칙 채점 |
| P3 | FRQ: 파트·채점 포인트, 채점 모듈 이식, 검수, 기존 콘텐츠 이전 |
| 출시 | AP Chem 출시, 기존 앱 종료 |
| E1 | 태깅 파이프라인, 단순 집계, 유사 문제, 진단고사 |
| E2 | FRQ 포인트별 오류 코드 후보, MCQ·FRQ 통합 집계 |
| F | 약점 상태, 처방, 확인 문항, 학부모, 다른 과목 |

- 브리프 단계와의 대응: 단계 2 = P0~P2, 단계 3 = E1, 단계 4 = P3 + E2
- 브리프와 다른 점: 새 앱은 출시 시점에 MCQ와 FRQ를 모두 갖춰야 하므로 FRQ(P3)가 출시 전으로 당겨졌다. 대신 브리프 단계 4의 "운영 데이터 이전"은 "콘텐츠 이전"으로 줄었다.
